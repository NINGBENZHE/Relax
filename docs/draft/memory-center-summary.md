# Relax Memory：当前设计与交付总结

状态：2026-11-17，可运行原型与后续设计。本文区分已实现能力、已知问题和目标架构，不代表生产验收。

配套：[产品方案](./memory-center-product.md)、[技术设计](./memory-center-design.md)、[Demo 手册](./memory-center-demo.md)、[原生记忆方案](./native-memory-design.md)。

## 产品定位与部署

Memory 为原有 Agent 提供可追溯的项目知识、成功策略和失败教训。用户提交当前脚本、日志或 trace，Agent 结合授权历史提出下一步诊断建议；任务结束后沉淀候选经验，再经审核复用。知识覆盖目标包括项目架构、所有优化方向及其案例，但当前只以性能专题验证流程，尚未完成全项目知识整理。

本地形态使用 Python 标准库与 SQLite，无需 Docker、GPU、独立模型或 MemOS。Agent 可通过 stdio MCP 直接访问本地库；需要可视化管理时启动后台网页服务。共享形态使用远端 HTTP 服务，任务按需拉取授权内容，本地经验由用户显式选择后提交远端候选。容器部署必须将状态目录放在已有持久化挂载上，SQLite 文件不应依赖临时目录长期保存。

当前网页是单管理密钥的 Demo。数据库、中心密钥、运行日志和监听信息属于运行状态，不进入代码仓库。多业务隔离已在底层任务凭证和命名空间原型中验证；网页固定使用专用空间，尚未提供真实多用户身份和角色权限。

## 已交付能力

| 范围 | 当前实现 | 边界 |
| --- | --- | --- |
| 记忆存储 | 候选、精确去重、版本、更新、失效、有效期、固定快照、读取回执 | 非语义去重；固定旧快照不会因 TTL 自动撤销 |
| Agent 接口 | 本地与 HTTP 客户端；MCP search/get/propose/feedback | 未自动接管所有 Agent 的任务开始和恢复流程 |
| 网页中心 | 录入、筛选、审批、驳回、修订、老化、历史、真实检索预览 | 操作人是演示字段；不构成身份认证或不可篡改审计 |
| 同步示例 | 显式选择发布；远端固定检索结果缓存；来源与读取回执校验 | 非全库同步，尚无增量删除或即时撤回传播 |
| 性能原型 | 静态脚本观察、规范日志、Chrome trace、历史案例与建议报告 | 规则匹配，不执行脚本，不自动证明性能收益 |
| 外部后端 | 可选私域 MemOS 适配与验证入口 | 尚未对真实 MemOS 服务验收 |

网页与性能原型复用存储组件，但当前分别配置实例，不应直接把中心数据库交给未经工作流适配的公共网关。

## 记忆分层与标准化方向

“长期／短期”描述生命周期，“本地／云端”描述存储位置，二者不能等同。建议将内容类型、存储范围、信任状态和生命周期分别建模。

| 层次 | 内容 | 写入与使用策略 | 当前状态 |
| --- | --- | --- | --- |
| 工作上下文 | 当前输入、工具结果、实际注入的经验 | 按预算组装，仅携带任务所需内容 | 有读取回执，尚无统一上下文组装器 |
| 任务状态 | 目标、约束、代码状态、观察、尝试、未决问题、下一步、证据引用 | 自动写私有空间，恢复时复用；不要求每条工作笔记审批 | 待实现 TaskState |
| 项目知识 | 架构事实、接口约束、适用范围 | 从授权来源整理，绑定来源版本 | 有通用记录，缺知识地图和来源失效传播 |
| 经历与经验 | 实验案例、成功策略、失败教训 | 候选校验、审批、版本与老化 | 当前原型重点 |
| 程序性知识 | 经过验证的操作方法、配方和 skills | 走代码审查与版本管理；检索内容不能提升为系统指令 | 已有操作 skill，未自动生成或升级 skill |

当前记录包含类型、领域、标题、摘要、正文、证据、审核声明、生命周期、版本和扩展信息。中心表单提供来源、适用条件、标签、证据等级、负责人、复核时间和过期时间。字段定义和实际 API 见技术设计；完整代码指纹、结构化环境约束和实验对照仍是目标格式。

后续应将审批决定、证据强度、适用性和生命周期独立表达。批准入库只代表接受该条声明与来源，不能自动推导结论经过实验验证。当前中心批准及授权缓存复制使用底层 `verification.state=verified`，虽然另有证据等级和限定 claims，下游仍可能误读，需调整契约。

## 优先待优化项

1. **修复缓存生命周期丢失。** 当前 `examples/memory/sync.py` 的 pull 会重建候选，提交时未传入远端 `expires_at`／`review_after`，本地副本可能不再按原时间过期。此问题已通过临时 SQLite 场景复现，本次提交保留现状并明确记录；修复时应保留生命周期，同时维持旧快照可重放语义。
2. **统一中心与 Agent 的工作流契约。** 检索只返回被授权且符合工作流状态的内容；不能绕过中心审批表直接消费候选。
3. **补齐 TaskState 和上下文组装。** 先按权限与环境适用性筛选，再检索短卡片，按需展开证据，记录实际送给模型的内容。现有关键词与字节预算不等于模型 token 预算或适用性验证。
4. **支持来源变化与知识地图。** 代码、依赖和报告变更后标记相关经验待复核；支持冲突、替代和反例，展示各优化方向缺少哪些证据。
5. **完成共享服务治理。** 增加身份、角色、显式共享发布、分页、备份恢复、同步游标与撤回传播，再考虑大规模数据库替换。

## 验证与尚未交付范围

本次 CPU 回归覆盖 27 个用例，包含候选与版本、隔离、固定读取重放、TTL、中心审批可见性、事务失败回滚、HTTP、MCP 和启动行为。性能演示已经走过本地检索、候选复盘、选择发布、远端审核、缓存、隔离及离线读取；没有进行真实 GPU 性能实验。网页已做接口与 JavaScript 语法验证，尚未使用浏览器自动化完成点击验收。

未部署真实 MemOS，未进行 GPU／多节点集成测试，因为本阶段仅要求无需 GPU 的基础知识和经验记忆。Agentic 训练的批次快照绑定、奖励后提交、token/mask、恢复与独立评测空间仍待 Runtime 集成，不能把底层快照接口当作训练验收完成。

Cowork Miniapp 目前仅有接入意向，尚未创建或发布。hi-cli 是环境工具而非 Relax 依赖；安装不等于账号授权，也没有直接的 Miniapp 创建命令。后续需取得平台开发文档和支持的鉴权方式，确认数据库、草稿保存与运行契约后适配，保持“先创建草稿，不发布”的边界。

下一阶段的验收应让一个新 Agent 会话独立恢复任务，检索到适用且未过期的证据，说明哪些结论需要重验；以实际任务效果、错误建议、过期使用、上下文开销和端到端成本衡量记忆价值。
